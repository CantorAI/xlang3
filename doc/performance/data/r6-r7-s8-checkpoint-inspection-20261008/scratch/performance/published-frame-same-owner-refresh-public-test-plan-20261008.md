Proposal bd18ffd8e9c41c10a43110a531c9db24ec9503ab32a54a102dd4b239bf121429 is scratch-only and uncompiled/unexecuted. This plan introduces no new engine API or private-template test. Root chooses and runs an isolated trial after the current checkpoint.

Existing filenames were located with rg --files and the actual source was read. Reuse these durable checks unchanged:

* tests/fixtures/core/threading_runtime_edges.py:141–158 checks sys._current_frames from a worker and per-thread profile/trace setup immediately before it. tests/fixtures/compat_sections/standard_modules.py:1927–1942 already holds a worker in Event.wait and checks its reported function.
* tests/fixtures/core/debug_frame_metadata.py and debug_frame_source_edges.py check materialized frame metadata. tests/cpp/interpreter_tests.cpp:493–646 and tests/cpp/debug_session_tests.cpp check paused frames, globals, stepping and resume through the exported interpreter/debug session APIs.
* tests/fixtures/core/thread_target_lifetime.py and weakref_thread_lifetime.py check post-join ownership. Retain profile/trace/exception fixtures because the publication schedule and owning state are unchanged.

Append a bounded public-API case to the existing interpreter CPP target, using a shared heap audit and joined worker so no callback outlives stack state. Runtime::set_current_frame_stack, publish_current_frame_for_thread_inspection, current_frame_snapshots and clear_current_frame are all present in the current Release exports.def (lines 19830, 19297, 17482 and 17403). xlang_thread_current_ident is not exported: obtain the worker identifier through the existing public _thread.get_ident callable, not a private helper or duplicated runtime state.

1. Parse/lower a Module with two named functions and valid instruction positions through existing public APIs. Keep an owning globals Module/dict and the Module shared_ptr alive in the worker. Publish one RuntimeFrameView with function A, IP a and activation x, then replace only those scalars with function B, IP b and activation y and publish again. Pause the worker with host synchronization after each publication. The observer calls current_frame_snapshots({worker_ident}) and inspects the actual returned FrameObject/function, instruction and activation fields. Require the second publication to expose B/b/y although count, Module and globals owners are unchanged. Check the frame's globals identity and the same Module too. Release each materialized observer frame before testing later owner cleanup.
2. Publish two frames and then shrink back to one; check exact f_back/depth and updated scalar metadata. Replace the globals owner and then the Module owner at the same depth and verify their exact new identities. These calls must continue to use the existing fallback. Include missing module/globals/instruction pointers to match the existing None/zero snapshot behavior rather than reading a stale prior frame.
3. Put a sole native cleanup token in a caller-owned local_values vector. Publish with a nonzero local_count, then remove its actual caller owner while the published snapshot remains registered. Require one cleanup: neither unchanged-owner publication nor fallback may retain arbitrary locals, cells, closures or registers. Observe the existing empty cross-thread local snapshot; do not invent live exact-locals parity.
4. Change trace/profile owners between publications, publish, clear them and finally clear the worker frame. Use shared audits to prove changed hooks and old globals retire according to the existing owning state. Do not assume a hook's cleanup occurs while the source or a materialized Frame still owns it. The fast path must decline changed Value owners before any mutation.
5. Clear current-frame state in the worker before exit, join it, release materialized observer snapshots and the intentional source owners, and require exactly-once cleanup with no retained registry owners. Exercise a subsequent fresh worker/function so same-depth publication cannot preserve an old activation.

The fast path must fully prove every owner before touching scalar state. No ownership transfer or allocation occurs on success; any failed predicate reaches the original fallback without partial updates. Test code should assert semantic metadata/ownership and avoid reaching private PublishedRuntimeFrameState fields. An existing perf counter may be used later to quantify reduced retain/release traffic, but no new counter is needed for correctness and no gain is asserted here.

Only after those checks pass should root run the exact frozen pickle child (5295c899...) against preserved C5 and trial controls, keeping 2,460 dumps, original protocol/input, fresh CP byte/roundtrip audit, raw streams and source/binary pins unchanged. The initial 190-location sample is unscored; an isolated trial must establish both eligibility and performance.
