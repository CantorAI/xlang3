Concrete repeated work
1. functional_builtins.cpp:5832 registers hash with builtin_fast_adapter<...,1>.
   builtin_methods.h:94 already uses borrowed stack Values for the normal single
   argument. It does not create a heap argument vector or increment string RC.
   Runtime::register_native_builtin (runtime.cpp:1018) registers an internal
   NativeFunctionObject. This builtin does not cross SDK X3CallContext/package
   host conversion. CallArgsView (interpreter.h:45) holds register indices.
2. Ordinary warmed CALL still routes ops_call.h:2955 to call_native_function
   (:3737): counter eligibility, TLS error scratch, native monitoring/profile
   eligibility, indirect adapter callback. fast_releases_vm_lock defaults false,
   so hash does not normally unlock/relock the VM. Counter name locking is also
   absent when instrumentation is disabled (perf_counters.cpp:46).
3. builtin_hash (functional_builtins.cpp:5248) calls runtime_hash_value, which
   calls runtime_value_hash_key (value_hash.cpp:492). Primitive string reaches
   the final value_hash_key after weakref/instance/class/tuple/alias/set probes.
4. Within value_hash_key, BEFORE the exact-string branch (:371), its Object path
   calls value_int_like_hash (:362 -> bigint.cpp:931 -> value_to_payload:197).
   Failed conversion invokes object_get_attr for '__xlang3_int_value__' and
   '_value_' (bigint.cpp:216-217). It then calls int_payload_value (:366), whose
   first value_int_like_to_i64 (bigint.cpp:899) repeats both object_get_attr
   calls (:910 and :914). This is FOUR full generic failed attribute lookups.
   Exact strings eventually reach object_get_attr's 'object has no attributes'
   failure (object_model.cpp:4962). These generic probes are unnecessary for an
   immutable StringObject, but are required for Python/SDK instances carrying
   numeric payloads. No repeated byte hashing is necessary: string_object_hash
   (value.h:811) already loads/stores cached_hash with relaxed atomics.

First candidate and safety
Move the existing exact string branch before numeric probes, keeping the existing
Class identity fast branch first. The returned cached value and sentinel remapping
stay byte-for-byte the same. value_as_string tests exact ObjectKind::String; Python
str subclasses remain Instance objects and still use runtime hash hooks. Numeric
subclasses, enum payloads, native hooks, weakrefs, cached tuple/bytes semantics,
errors, builtin rebinding, tracing/profile/monitoring and call lifetime remain on
their unchanged paths. The source comment explains the avoided failed lookups.
The shared primitive benefits Python __hash__ returning hash(self.text), tuple
members, sets and mappings that call it; specialized string dict indexing already
uses string_object_hash directly and is an important unchanged control.

A guarded primitive native hash intrinsic is missing, but defer it until the
shared dispatch correction is measured. A later VM candidate could compute exact
string hash directly after proving canonical builtin callback identity, one plain
argument, no hooks/monitoring/debug, and safe result overwrite. Callable name or
the live builtins dictionary alone is not sufficient proof. Callee rebinding,
captured builtins, aliases, polymorphic arguments and output-finalizer reentry
must remain observable. Keep normal Next when the old output can finalize, and
read the complete hash before publishing an output that may alias the input.
Do not add byte/tuple caches or repeat accepted trivial/captured callback work.
