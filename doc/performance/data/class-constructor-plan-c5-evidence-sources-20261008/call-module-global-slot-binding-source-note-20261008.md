# CallModuleMethod global binding — current C5 source audit, held

The indexed design already exists. IR `CallModuleMethod.a` is an index in the compiled module's **global name list** (`module.global_slots`), while a live `ModuleObject` has its own `name_to_slot` map and `slots` vector. Metadata/native initialization and execution in an existing namespace can make those physical indices differ. Treating `in.a` as the live vector index would be incorrect.

The compiler emits this fused operation for an imported module name that is not a local/free variable (`src/sema/lower.cpp:6800`–6813). At every dispatch, `call_module_method` first resolves that imported name using `module_find_attr_slot(globals_module, module.global_slots[in.a], …)` (`src/executor/xlang_vm/ops/xlang_vm_ops_call.h:4875`). `module_find_attr_slot` performs `name_to_slot.find(name)` plus bounds/Invalid checks (`src/runtime/module_object.cpp:441`–454). This is a real string hash lookup. The native callable cache hit is later, after that binding resolution (`ops_call.h:5054`); it can avoid the second exported-attribute lookup but cannot avoid the first global name lookup. On native miss, Python/class/native-property/missing-module-attribute paths also resolve the export name (`ops_call.h:5075`) and preserve their existing dispatch.

`LoadModuleSlot` already has the complementary warm index path: `instr_cache.global.kind==1`, same globals-module version, physical-slot bounds and current slot non-Invalid, then reads the live slot (`ops_variables.h:352`–361). Its cold path reconciles the compiled index/name with the actual live mapping before publishing the physical slot (`ops_variables.h:363`–382). CallModuleMethod currently does not use that existing global payload, even though the instruction record contains separate global/call payloads. Indexed local variables and a cached native callback therefore do not eliminate this module-binding hash.

One bounded **unimplemented candidate** is to use CallModuleMethod's existing `instr_cache[ip].global` only for the imported global's physical slot, before the current native/export dispatch. On a kind1/version/bounds/non-Invalid hit, reread the current live value at the stored index. On a miss, execute the exact existing lookup and publish only scalar kind/index/version. Do not cache a callable, a Value, a vector element address, negative lookups, module properties, or `__getattr__` results; do not change profile/monitoring or callback/error behavior. Publication must happen before any later callback, and no proof may be restamped after callback cleanup with an old resolved value.

This narrow cache is **activation-only**. The active frame owns a captured `globals_module` and does not substitute its namespace during the activation. `clear_cache_if_owned` explicitly clears the global payload before retaining any CallMethod scalar cache (`xlang_frame.h:609`), including the ownerless early-return path. Frame reset/return must keep that clearing contract. Generator suspension can retain the same active frame/namespace, but return and pooled-frame reuse must discard this binding. This requires no new cache owners, no new structure fields, and no name-to-slot representation replacement. Do not preserve this scalar cache across returned activations using a weak module pointer plus `ModuleObject.version`: module versions currently start at0 (`module_object.h:33`) and increment locally, so pointer/version equality would not prove a freed/reused module's identity. A wider persistent cache is a distinct unproved design, not part of this candidate.

Completed mutation paths advance module versions, including writes/deletes through its namespace dict, which delegate to module setters/deleters (`mapping.cpp:1141`–1147,1374–1380,1287,1418). Native module descriptors, missing exported attributes, a rebound nonmodule imported name, and pending errors keep the existing path. Module mutation currently releases some old slot owners before its version increment (`module_object.cpp:385`–405); this proposal must read only the live slot and must not treat a copied callable or borrowed vector pointer as an equivalent proof. It does not repair or broaden existing native-function cache lifetime semantics.

Minimum later correctness/admission proof: one actual DLL function loops at one CallModuleMethod site under an imported binding whose compiled/physical indices differ; verify the scalar global payload becomes kind1 with the correct physical index, never acquires a Value owner, and is cleared on pop. Within that same loop, rebind the imported name to another module, delete/recreate it, mutate via `globals()`/module dict, grow slots, and rebind to a nonmodule callable-attribute object. Export mutation/missing `__getattr__`, native property, callback-raised exception identity, returned-frame reuse with another namespace, and profile/monitor events must retain the existing strict behavior. The original source workload and fixed gate remain the performance decision; no runtime probe or test is executed here.

The likely benefit is limited: a one-call-per-short-activation site sees a cold binding again. Current Python3.14.7 `pickle.py` has `io.BytesIO()` in `_dumps` (1866), `_Framer.start_framing` (203), and `_Framer.commit_frame` (232). Existing retained older pickle IR shows CallModuleMethod at the framing sites, but that dump is historical and is not presented as fresh C5 IR. The fresh C5 pickle native sample has only **4/190 leaf samples (2.1%)** at `module_find_attr_slot`, and6/190 overlapping inclusive samples. It does not count which callers or which of the two lookups those samples represent and does not establish a dominant/removable cost. C1 pprint's18/438 is older candidate/workload evidence, not the C5 pickle share.

Prior rejected trials matter: the Oct5 module Python-function call cache did not significantly improve original json_dumps; Oct4 caching only the typed module pointer did not improve original async_tree_eager; Oct6 same-module globals save/restore bypass was neutral on pure pickle and regressed subparsers; the Oct6 builtin-global slot cache did not give repeatable gains. None proves this distinct first-binding cache fails, but they argue against attributing a20x whole-workload gap to one hash lookup or repeating broader weak-owner/typed-module/function-target cache trials without measured activation reuse. A small proof may justify this candidate; the present evidence does not make it a high-confidence material gain.
