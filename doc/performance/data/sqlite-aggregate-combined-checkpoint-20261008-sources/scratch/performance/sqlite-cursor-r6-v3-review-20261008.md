# SQLite cursor completion R6 v3

R5's candidate passed the first five original aggregate groups but failed factory replacement after a one-row `fetchone`. Root's retained-cursor observation isolated this from temporary ownership: CPython accepted replacement after the first row; XLang3 raised OperationalError until a second fetch exhausted SQL. Raw evidence is preserved under `doc/performance/data/sqlite-aggregate-cursor-observe-*-20261008.log` and the original failed R5 validation record.

The generic cursor fix follows [CPython 3.14.7's native cursor progression](https://raw.githubusercontent.com/python/cpython/v3.14.7/Modules/_sqlite/cursor.c): execute primes a row; fetch copies that current row and advances before returning; lookahead failure discards the copied row; completion releases the active statement. DML RETURNING completes its rowcount at DONE. Cached description survives exhaustion. This changes our own native module, with the Python wrapper and aggregate algorithms remaining Python.

This complete incremental patch applies over actual R5, not v1/v2. Earlier proposals remain unchanged. It caches column names as native strings, then detaches and finalizes completed/error statements. Reset-only completed cursors would retain close-v2 zombie resources and registered factories. Description reads the cached names after native statement release. Exhausted fetches cannot silently restart SQL.

`Cursor.execute` owns SQL text immediately after SDK conversion, before prior-statement cleanup can execute Python and overwrite the thread-local SDK string buffer. It revalidates the connection after that cleanup. Operation metadata is derived before binding/stepping. Statement error reporting uses its captured live DB before finalization, and no captured DB is read after finalization.

Every statement writer is covered: execute, fetchone and close have RAII busy guards; executescript also owns its script text, takes the guard and detaches before finalizing; executemany rejects locked entry before len/getitem callbacks and metadata mutation, while its internal execute calls acquire their usual guards. Iterator/fetchall share fetchone; context exit shares close. The lookahead guard is intentionally conservative: CPython unlocks before its lookahead step and has cached Statement object ownership, while this native representation owns a raw statement. R6 rejects same-cursor callback operations during that step to avoid freeing active storage. No parity claim is made for that reentrant edge. Unrelated cursors and connection close remain permitted.

Root captured all eight new cursor fixture groups passing on exact CPython 3.14.7. The original seven-group aggregate fixture and all R5 C++ ownership assertions remain unchanged.

Its executemany parameters raise if observed, proving rejection precedes argument callbacks. It must be captured on CPython 3.14.7 and candidate independently; this reviewer has not executed it. This probe does not replace or weaken either registered fixture.

Static generation and apply-check pass. No actual engine/test files, builds or runtime processes were changed/launched by this reviewer.
