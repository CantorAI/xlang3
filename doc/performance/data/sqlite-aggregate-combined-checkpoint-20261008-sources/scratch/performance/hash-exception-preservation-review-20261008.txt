Exception transfer is already correct until builtin_hash:
- runtime_value_hash_key, value_hash.cpp:529, dispatches __hash__ through
  runtime_call_callable and returns false without changing the pending object.
- Nested Interpreter::run_function stores result.exception and pending exception
  in xlang_vm_loop.cpp:1928. run_function_value retains that object when needed
  (xlang_interpreter.cpp:226-231).
- runtime_call_callable, functional_iterators.cpp:379-396, transfers the precise
  RuntimeResult.exception into runtime pending state. It also preserves a pending
  exception when only the error vector is present. Its diagnostic error text is
  intentionally separate from the Python exception object.
- builtin_hash, functional_builtins.cpp:5254, unconditionally calls
  raise_class_error(TypeError or ValueError, error). Runtime::raise_class_error
  at exceptions.cpp:169 replaces pending state with a NEW exception. This is
  where the original class, identity, traceback and explicit cause are lost.
- VM native failure dispatch in ops_call.h takes the resulting pending object;
  it cannot recover the overwritten original. There is no missing ABI transfer.

Bounded repair: when hashing fails, take and immediately restore any pending
exception. Synthesize the existing TypeError/ValueError fallback only if none is
pending. This follows existing min/AST conversion-error helpers at
functional_builtins.cpp:3087/617. It changes only the failure branch; successful
hashing pays no new guard, allocation, callback or exception ownership work.
Do not change Runtime::raise_class_error globally: intentional new raises must
remain able to replace pending state. Pure Python library algorithms stay Python.

Ownership/API scope: take_pending_exception acquires an owned Value before
clearing pending state; set_pending_exception receives it by move. There is no
unowned exception interval, suppression, type conversion, replay of __hash__,
or modification to diagnostic text. Pending state is the existing native error
protocol: callers should enter with no unrelated pending error; if one is already
present at a failing native boundary, this proposal retains it exactly as the
existing preserving helpers do. Success behavior with pre-existing pending state
is unchanged. This is generic builtin hash behavior, not full hash conformance.
