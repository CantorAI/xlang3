# Coverage native-tracer boundary: bounded source audit

The missing native backend is a concrete, potentially broader boundary than repeated f_code allocation: the Python tracer's whole callback body runs for every delivered event, while the native backend executes that event logic natively. Current evidence does not establish which cost dominates CPU time or predict a speedup. A frame f_code cache removes repeated materialization while retaining the Python tracer route.

Collector-visible contract (collector.py:276–302; tracer.pyi:8–33; types.py:78–104):

- Mandatory writable tracer fields: data, trace_arcs, should_trace, should_trace_cache, warn.
- Conditionally assigned fields, controlled by hasattr: concur_id_func, file_tracers, threading, check_include, should_start_context, switch_context, disable_plugin. Native stub advertises all except threading; that conditional must be preserved rather than assumed mandatory.
- Tracer construction with no arguments; start() returns a usable trace callable, stop(), activity(), reset_activity(), get_stats(). Collector pauses/resumes nested collectors, starts one tracer per thread, and its thread installation hook immediately invokes the returned callable (collector.py:304–324/327–396). Exact returned callable identity, callable/repr/error behavior and statistics shape need CP observations/native source before compatibility claims.
- CFileDisposition construction plus writable original_filename, canonical_filename, source_filename, trace, reason, file_tracer, has_dynamic_filename (tracer.pyi:8–17, disposition.py:31–41). A CTracer-only import without CFileDisposition would not satisfy this package's import contract.
- Setting HAS_CTRACER changes plugin and packed-arc behavior, not only speed. Collector flush_data at449–478 decodes20-bit line numbers with negative-sign flags atbits40/41. Native backend must preserve this representation and plugin/dynamic filename/context/concurrency behavior, or it would overstate compatibility by enabling those flags.

Existing XLang3 delivery can avoid a Python function callback per event without adding a new raw-frame hook. sys_settrace (src/runtime/modules/system/sys_module.cpp:2316–2322) stores an owning Value through Runtime::set_trace_function (runtime.cpp:1122–1141), including saved nested thread states and publication-before-retirement. The VM emitter (xlang_vm_loop.cpp:1279–1394) pins the selected hook, publishes frame state, materializes or refreshes the retained FrameObject and a locals dict, suppresses recursive trace dispatch, calls runtime_call_callable, and installs the returned local hook. runtime_call_callable's NativeFunction branch (functional_iterators.cpp:290–325) invokes the native callback directly; a Python Function uses Python execution instead. No separate public raw-frame C trace callback slot was found in Runtime's trace/debug declarations. The own native callable route still pays Frame/locals/event argument construction and native monitoring semantics; it is not equivalent to CPython's internal C trace ABI.

PyTracer._trace (pytracer.py:115–271) reads f_code, manages a per-frame data stack, selects filename/disposition, updates Python sets, handles contexts, and decodes co_code/f_lasti for generator call/return distinctions. start/stop at273–325 use sys.settrace and trace identity/thread checks. A native backend must preserve this package-visible behavior through XLang3's existing event protocol, keep should_trace/context/warn/plugin callbacks Python when called, and maintain owning roots/GC edges for shared data, callbacks and per-thread state. It must not reuse CPython's DLL or rewrite coverage.py's pure-Python collector/library. Local native-extension presence makes an own compatible coverage.tracer substitution allowable in scope; it does not make implementation or ABI parity already proven.

Unresolved compatibility includes generator suspension/resume/exception arcs, thread stop/pause/resume and nested collectors, trace-hook replacement and error propagation, dynamic source plugins/concurrency IDs, callback reentry/retirement/weakref/GC ownership, and the disclosed existing Frame.f_code canonical-function/assigned-metadata differences. None is silently repaired or waived by this audit. No new module, fixture, instrumentation, benchmark, runtime process or build was authored or executed. Source hashes accompany this note; they are file-observation identities, not a complete compiler-input or timing proof.
