# Non-fused branch calls: source comparison after L9 preparation

Source-only comparison, with official CPython v3.14.7 sources browsed. No engine/test edit, import, AST, runtime, dump, build, or timing was performed. L9 remains a separately measured trial.

The diagnostic `benchmarks/diagnostics/python_callback_boundary.py` calls `branch(value)` inside `branch_calls`; its condition prevents the existing trivial-body shortcut. Its local/argument names are indexed, but each call still enters a real VM frame. Indexed name access removes string lookup; it does not eliminate call entry, argument ownership, inspection publication, dispatch, or cleanup.

CPython's [bytecodes.c](https://raw.githubusercontent.com/python/cpython/v3.14.7/Python/bytecodes.c) lines 3659–3727 guards function version, exact arity, stack space, recursion and the custom evaluator before transferring argument stack references and switching frames. `RETURN_VALUE` lines 1101–1115 unlinks the dying frame, clears it, and resumes the caller. The [frame header](https://raw.githubusercontent.com/python/cpython/v3.14.7/Include/internal/pycore_interpframe.h) lines 173–201 initializes frame fields and remaining local slots; lines 325–336 advances the thread data-stack pointer. It does not initialize the whole evaluation-stack capacity. [frame.c](https://raw.githubusercontent.com/python/cpython/v3.14.7/Python/frame.c) lines 85–120 clears occupied local/stack references and preserves escaped frame ownership. General native/vector entry still performs binding in [ceval.c](https://raw.githubusercontent.com/python/cpython/v3.14.7/Python/ceval.c) lines 1860–1877 and 1958–2000; the specialized Python-to-Python route is the relevant comparison for `branch_calls`.

XLang3's direct `Call` uses the cached UserFunction route at `ops/xlang_vm_ops_call.h:3118`, then `call_user_function:4451`, and `push_frame` at `xlang_vm_loop.cpp:979`. Exact simple signatures already bypass generic argument binding. `reset_after_clear` (`xlang_value_buffer.h:223`) already preserves cleared shared slots instead of filling every existing slot again. Same-function reuse also skips cache reset at `xlang_frame.h:462`; consequently L9's immutable-map optimization principally changes fresh native reentries, rather than every warm inner call in `branch_calls`.

Every real call still resets frame identity/state (`xlang_frame.h:421–480`), binds locals, allocates an activation ID (`xlang_vm_loop.cpp:1174`), publishes current-frame views and identity on both push and pop (`:2050–2090`), and clears owning locals/cells plus object-bearing register slots (`xlang_frame.h:485–517`). These are reachable source operations, not an attribution of the observed multi-x gap. CPython also preserves function/code ownership, recursion, monitoring, errors, and escaping frames; omitting those obligations is not an equivalent optimization.

Two bounded future experiments are supported by current source:

1. **Select the final module owner once.** `call_user_function:4465–4470` first copies caller `module_owner`, then replaces that temporary with `fn_obj->module` whenever the callee has its own owner. Initialize the selected shared owner directly from the callee or legacy caller fallback. Preserve target lifetime before any callback, invalid-ID/generator handling, and the owned pointer passed to `push_frame`. The active caller already owns its module, so eliminating the discarded temporary introduces no last-owner finalization. Test same-module, different-module, legacy null callee-module, code replacement, nested failures and owner cleanup. This changes neither argument transfer nor frame lifetime.

2. **Coalesce common frame identity publication.** At each frame switch, loop lines 2080–2090 calls `set_current_globals_module`, `set_current_frame_locals`, and `set_current_frame`. Each reaches `current_frame_state` (`runtime.cpp:157`), which already guards a cached same-Runtime TLS pointer before using the per-thread map. The common path therefore repeats two extra exported Runtime calls/TLS guards, not three hash lookups. A single Runtime operation can handle the common exact same Object owner in `state.current_globals_module`: retain the existing owner and perform the same local pointers/count and frame owner/function/IP writes in their existing order after one state lookup. Different/invalid globals must retain the existing setter path, including old-owner cleanup and any reentry. No materialized snapshot owner is reused and no registry or cross-thread publication is skipped. Test active/escaped frames, profile/trace/monitor callbacks, changed-globals cleanup reentry and nested Runtime entries.

Prior proposals excluded: rejected scoped Interpreter reuse (34.4131887 s versus previous 33.134718 s, unpaired), rejected R6 materialized snapshot-owner reuse, September 29 signature metadata trials, and October 4 direct exact-positional cache trial. Their evidence remains in the existing rollback/provenance and performance documents. No new patch or measurable-gain claim is made here. Compare the unchanged branching direct-call and native sorted-callback diagnostics separately; then retain original workload correctness, fixed gate and official evidence for any actual trial.
