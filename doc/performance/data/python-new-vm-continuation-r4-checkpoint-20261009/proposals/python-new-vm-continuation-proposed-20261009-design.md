## Boundary and existing semantics

The ordinary custom-new class path selects `__new__`, copies/materializes original arguments, and calls `runtime_call_callable_kw`; its plain Python Function branch creates a fresh Interpreter. After return it checks the actual result type, resolves a fresh initializer, skips the exact default object initializer, and ignores other initializer return values. Direct saved-new calls instead enter `call_user_function` and push a normal VM frame.

The candidate pushes a normal synchronous Function frame from ordinary `Call`, and from `CallEx` only when positional expansion consists entirely of exact Tuple objects and there are no keywords or ** mappings. It changes no Python body or result algorithm. The exact-tuple path follows the existing helper's explicit-then-star order and executes no iteration callbacks. Unsupported expansion declines before materialization or execution; the original path executes once. Native _pickle class entry through `runtime_call_callable_kw` remains unchanged.

Admission requires the current builtin-type metaclass identity, no native type constructor, a raw Function or exact StaticMethod containing a Function selected by the existing resolver, a non-null live module/valid ID and non-generator/non-async/non-coroutine IR, no initially active monitoring/profile/trace/debugger or pending interpreter events, and a non-generator, non-paused root invocation. Custom descriptors, ClassMethods, native new, custom metaclasses, arbitrary argument expansion, and all keywords keep the old route. There is no cached selection or cross-activation owner.

An owning private tuple contains selected-new callable, called class, and every original flattened positional argument. Copy construction converts borrowed values into owners before frame entry. The tuple is carried in the existing continuation Value. Existing frame move, GC visiting, pause storage and unwind cleanup therefore need no new Value fields. Two return-mode tags are appended without changing older tag ordinals.

At new-frame completion, existing return observers and frame-local cleanup run first. The caller is republished and its active callsite is exposed before any new callback. Current result class/subclass and current initializer are resolved afresh, so mutation of initializer, MRO, code or cleanup hooks in __new__ is not frozen. A plain bound synchronous initializer uses a normal frame push and carries a second tuple owning result, original context and selected initializer through its body and final output replacement. Other initializer callables use the existing synchronous runtime dispatcher. Missing/default initialization and foreign results publish directly. No new unlock/relock sequence is added.

Exceptions use the existing VM dispatch and exact pending-exception transport. A handled binder error or deferred recursion error does not retry __new__. The active caller remains at the Call instruction during fresh lookup/synchronous initialization; successful init push or synchronous completion advances it once. Frame references are reacquired after push. Output replacement occurs while selected callable/class/arguments/result remain owned. The prototype still requires root compiler and exception/reentry audits and execution; these are design requirements, not already observed behavior.

The current `object_get_attr` initializer policy, ignored non-None init return policy of custom-new calls, and partial escaped-frame locals policy are retained; this does not claim complete CPython parity in those unrelated areas. No compiler/IR format changes occur, so the source-cache magic and codec are unchanged.

## Affected benchmark boundary

No official affected-case eligibility has yet been measured.
