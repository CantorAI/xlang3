# XLang3 Benchmarks

## Regression gate

Compilation remains independent of timing. Before changing the engine, retain
a Release executable and its adjacent runtime DLL/shared libraries in a
separate directory. Use the same architecture, compiler, and build settings.
Both engines must support the native `time.perf_counter` function (the August
17 build predates that module; keep its historical process-time comparison).

```powershell
python benchmarks/check_regression.py --baseline scratch/performance-baseline/xlang3.exe --candidate build/Release/xlang3.exe
```

This runs eight fixed workloads on both executables, alternates execution
order, verifies equal output, excludes startup with internal timing, and saves
raw samples, benchmark hashes, runtime hashes, and paired bootstrap intervals
to `scratch/performance/latest.json`. It uses 21 measured samples after five warmup rounds. Each sample runs both baseline-candidate and candidate-baseline process orders, then combines same-position timings geometrically to reduce launch-position bias. Workload loops, output checks, and the 10% per-case slowdown limit are unchanged.
Any case more than 10% slower with a 95% bootstrap interval wholly above the
threshold must reproduce in a second fresh run to be a confirmed failure.
Mixed or uncertain results are inconclusive, not successful. Bootstrap
intervals characterize these samples, not all possible system noise.

Exit codes: **0 pass**, **1 confirmed regression**, **2 invalid/inconclusive**.
Keep the machine idle and finish all builds before running. Run engines from
separate directories; the baseline must never be overwritten by the candidate
build. Missing files, crashes, timeouts, mismatched output, or a runtime changed
during measurement fail closed. Use the complete default suite for validation;
`--cases` is for diagnosis only. The existing `run.py` remains an exploratory
CPython comparison, not the regression gate.

The compatibility loop enforces this check using `repo.performance_baseline`
and `repo.performance_report` in `agent/config.toml`, even with `--skip-tests`.
A baseline is a local build artifact and is not downloaded or generated by the
gate. On a new machine build and preserve the accepted revision first. Never
silently refresh the accepted baseline: doing so would hide cumulative loss.
See `AGENTS.md` for the acceptance policy. This initial gate protects the
covered workloads; extend it for new performance-critical engine features and
representative application workloads. It does not prove all programs cannot
regress, nor does a current-build baseline resolve the existing August gap.

Gate self-tests: `python -m unittest discover -s benchmarks/tests -v`.

Benchmarks compare XLang3 against CPython on the same pure Python source files.

Initial goals:

- keep benchmark sources small and readable
- compare interpreter-only XLang3 first
- record command lines, Python version, compiler, CPU, and build mode
- avoid benchmarking startup cost unless the benchmark is explicitly about startup

Current groups:

- `scalar_arithmetic`: integer and floating-point operator dispatch
- `local_slots`: local variable load/store and loop behavior
- `function_calls`: direct function calls and argument passing
- `class_construct`: class calls, `__init__`, instance attributes, and method calls
- `branches`: if/else and comparison dispatch
- `list_append`: native method binding and list append behavior
- `range_for`: range iteration and for-loop dispatch
- `threading_parallel_sum`: CPython-compatible threaded chunk work, lock-protected result collection, and join behavior

Additional tracks:

- `cases/`: XLang3 microbenchmarks for IR and interpreter tuning.
- `pyperformance/`: integration notes and helper scripts for the Python ecosystem benchmark suite.

XLang3 runs `.py` files directly. Benchmark files should therefore be valid Python files that can run on both CPython and XLang3 whenever the implemented language subset allows it.

The first milestone is not to beat CPython everywhere. It is to make interpreter performance visible early, especially where `X3Value` scalar fast paths and sema-assigned local slots should help.

Run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\benchmarks\run.ps1 -XLang3 .\build\Release\xlang3.exe -Python python
```

For the larger Python benchmark suite, see `benchmarks/pyperformance/README.md`.
